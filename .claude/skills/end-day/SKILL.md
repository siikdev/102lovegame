# /end-day — 세션 마무리 & 핸드오프

목표: 다음 세션이 **아무 맥락 없이도** 이어받을 수 있는 상태로 멈춘다.

## 절차

0. **품질 감사 오케스트레이션** — 아래 스킬을 순서대로 실행 (각각 단독 실행도 가능):
   1. `/review-arch` — 모듈화·flag·bus·adapter·백엔드 전환 용이성 점검
   2. `/review-docs` — 문서 신선도 (불일치 즉시 수정)
   3. `/review-data` — docs/DATA.md 데이터 구조 문서 갱신
   4. `/research-improvements` — 급조된 기능 1~2개 베스트 프랙티스 조사 (검색 2~4회 제한)
   5. `/propose-features` — 위 결과 + 세션 중 아이디어를 docs/BACKLOG.md 에 수확
   변경 규모가 작았던 날은 각 스킬이 "통과" 한 줄로 끝나도 된다 — 형식적으로 늘어놓지 말 것.
1. **열린 작업 점검**: `git worktree list` + 각 워크트리 `git status` — 미커밋 변경 수거.
2. **상황별 마무리** (docs/GIT_WORKFLOW.md 준수):
   - **기능 완성** → 검증(아래 3) → rebase → `merge --ff-only` → `git push`(자동 배포) → 라이브 200 확인 → 워크트리/브랜치 삭제 → 기능이면 태그(v0.MINOR.0) 검토
   - **기능 미완** → 컴파일되는 지점에서 커밋(진짜 중간이면 `wip:` 접두) → 브랜치에 push(백업) → 워크트리는 **유지** → 멈춘 지점·다음 단계를 HANDOFF에 구체적으로
   - **실험 실패/폐기** → 브랜치 삭제, HANDOFF '실패한 접근'에 이유 기록 (재시도 방지)
3. **검증**: 변경된 JS는 `.mjs` 복사 후 `node --check`; push 했으면 1~2분 후 라이브에 반영 확인.
4. **HANDOFF 갱신**: `docs/HANDOFF.md` 를 아래 양식으로 **덮어쓰기** (100줄 이하, 과거 이력은 git 에 있음):
   ```markdown
   # HANDOFF — 마지막 세션: YYYY-MM-DD
   ## ✅ 이번에 한 것          <- 커밋 요약 3-6줄
   ## 🔨 진행 중 (멈춘 지점)    <- 브랜치명 + 어느 파일 어느 단계에서 멈췄는지, 없으면 "없음 — 클린"
   ## ⏭️ 다음 할 일 (우선순위)  <- 1. 2. 3. 구체적 행동 단위, 첫 항목은 바로 실행 가능하게 (BACKLOG 상위 항목과 동기화)
   ## 🧠 결정/주의사항          <- 왜 그렇게 했는지, 건드리면 안 되는 것
   ## ❌ 실패한 접근            <- 시도했다 버린 것 + 이유 (없으면 생략)
   ## 🌐 상태                  <- main 커밋 해시, 라이브 URL 정상 여부, 열린 워크트리
   ```
5. **HANDOFF 커밋·push**: `chore(handoff): YYYY-MM-DD 세션 마무리` — 이 커밋만은 main 직접 커밋 허용 (GIT_WORKFLOW 예외).
6. **마지막 보고**: 오늘 한 것 / 남긴 것 / 내일 첫 행동 — 3줄 요약.

## 규칙

- 절대 미커밋 상태로 끝내지 않는다 (워크트리는 삭제될 수 있음)
- main 에는 동작하는 상태만 — 애매하면 병합하지 말고 브랜치에 남겨라
- HANDOFF 는 "다음 세션의 나"가 읽는다는 가정으로: 추상 금지, 파일 경로·명령어 수준으로
