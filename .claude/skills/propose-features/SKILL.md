# /propose-features — 백로그 갱신

목표: "다음에 뭘 하면 좋을지"가 머릿속이 아니라 `docs/BACKLOG.md` 에 남게 한다. 아이디어는 평가와 함께 — 나열만 하는 백로그는 죽은 문서다.

## 절차

1. **수확**: 이번 세션에서 ① 사용자가 지나가듯 말한 불편 ② 구현하며 느낀 마찰 ③ review-arch/docs/data 가 넘긴 항목 ④ 새 아이디어 (0~5개, 억지로 채우지 않기)
2. **평가해서 기록** — 각 항목 양식:
   ```markdown
   ### <이름>  `우선순위: 상|중|하` `노력: S|M|L` `상태: 제안|승인|진행|보류`
   한 줄 설명. **가치**: 왜 좋은가. **접근**: 어떻게 만들까 (기술 선택 포함). **리스크/의존**: 있으면.
   ```
3. **정리**: 완료된 항목은 삭제(이력은 git), 사용자가 거절한 건 `보류` + 이유. 상태 변경은 사용자 결정만으로 (`제안`→`승인`은 Claude 가 임의로 하지 않는다)
4. 상위 2~3개를 /end-day 의 HANDOFF '다음 할 일' 과 동기화 — /start-day 브리핑이 이걸 읽는다

## 원칙

- 하네스 준수 전제로 제안 (feature flag 로 끌 수 있는 형태, adapter/stats.js 확장 지점 활용)
- 멤버·데이터 하드코딩을 유발하는 제안 금지
- 비용 발생(유료 API 등) 제안은 무료 대안과 함께 제시
